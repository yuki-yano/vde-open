# ADR-0011: 質問と回答は、作ったときの版に固定し、管理UIの送信でだけ確定する

状態: 採用（P5）

## 背景

仕様11章は、Agentが人に質問し、人が管理UIで回答できることを求める。回答は、Agentの作業の前提になるので、取り違え（別の版・別の回答案・二重の確定）があってはならない。回答案（送信前の入力）を別のAgentが読んで、人の確定の前に作業を進める経路も作らない。

## 決定

- 質問定義は、決まった形（仕様11.2の固定のsubset）だけを受け付ける。原文を自前のJSON parserで読み、重複したkeyと`__proto__` keyを拒否してから、Zodで検証する（Zodのrecordは`__proto__`を黙って捨てるので、parserの段階で拒否する）。同梱のmeta-schema（`packages/shared/schemas/questionnaire.schema.json`）とZodの契約は、contract testで一致を確かめる。
- 回答案の検証は、あるfieldの型・値・大きさ（選択肢、数の範囲、最大の長さ・個数）だけ。必須と最小の条件（`minLength`・`minItems`）は送信のときに検証する（入力の途中で、未完成を理由に保存を拒まない）。管理UIでは、入力欄が空なら未入力としてfieldを省く。空の回答（空の文字列・空の配列）がschemaで有効な必須のfieldには、空の回答を明示する欄を出し、未入力と区別する（仕様11.2「空文字を許すかはminLengthで定義」）。選択肢は位置で指し、空の文字列の選択肢を未選択と取り違えない。
- 質問は、作ったときの文書の版に固定する。固定した版は、質問の記録を消すまで、文書の版の整理（直近2版と5分以内）から外す。容量の上限を超える新しい操作はerrorにし、固定した版の内容は消さない。
- 状態は`pending`から`submitted`か`cancelled`へだけ進む。文書を閉じると、同じcommitで回答待ちの質問を`cancelled`（`document_closed`）にする。取得済みの印（`ack`）は状態とは別に持ち、明示的に付ける。読むだけでは付けない。
- Agent向けの取得（`get`・`list`・`wait`）は、確定した回答だけを返す。回答案と質問定義は返さない。管理UI向けの取得だけが、回答案と質問定義と文書の現在の版を含む。
- 送信は、送信ID・もとにした回答案の版・固定した版・確認した現在の版・旧版への回答の確認を受け取り、確定する内容はserverが保存済みの回答案から取る（回答そのものは受け取らない）。条件はhashにして記録し、同じ送信IDで同じ条件の再送には同じ結果を返し、違う条件なら競合にする。新しい版があるときは、管理UIで旧版への回答であることを確認した場合だけ確定し、確認した後にさらに版が変われば確認し直してもらう。
- 1つの文書に、回答待ちの質問は1件だけ。`--operation-id`は、質問する先と質問の内容のhashと組で記録し、同じ組の再送は同じ質問を返す。
- `--view`は、文書を開くcommitと質問を作るcommitが別になる（開いた後に質問の作成が失敗しても、文書は開いたまま）。質問だけのとき（`--document`も`--view`もない）は、質問のtitleと説明を内容とする文書を、質問と同じcommitで作る。
- 待機（`feedback wait`）は、daemonの中で質問の変化を待つ。CLIは期限を開始時に決め、接続（必要ならdaemonの起動）・再接続・応答の待ちを、すべてその期限で打ち切る。daemonが止まったり再起動したりしたら、残りの時間の範囲で接続し直す（期限は延ばさない）。daemonへは、接続した後の残りの時間を渡す。待機を終えたら、まだ動いている接続の処理（daemonの起動の待ち、接続の確認、再接続の間隔）も止め、CLIのprocessを残さない。時間切れは終了コード6、SIGINTは130で、どちらも質問は回答待ちのまま。daemonの停止では、待っている要求を先に終わらせてから、受け付け済みの処理の完了を待つ。
- 管理UIは、回答待ちの間は固定した版を表示し続ける。固定した版は「Pause updates」（更新を止める）より優先し、その間は「Pause updates」を操作できない。回答の要約と送信buttonは、文書の表示の外の回答panelに置く。formを使わず、Enterで送信しない。回答案は入力が止まって300ms後に保存し、別の画面が先に更新していたら、上書きせずに最新の回答案を表示し直す。管理UIは、知っている回答案の版（取得した版か、自分が保存した版）より古い取得結果を使わない。確定・中止した質問は、serverの内容（確定した回答、なければ保存済みの回答案）を表示し、その画面の未保存の入力を見せない。旧版への回答の確認は、確認したときの文書の版に結び付け、版がさらに変われば確認し直してもらう。通知の再接続・連番の欠け・`resync-required`では、一覧と質問を取り直す。
- 変更の通知（`feedback-changed`）は、質問のID・状態・回答案の版・取得済みかだけを運ぶ。

## 影響

- `--view`の文書を開いた後に質問の作成が失敗すると、文書は開いたまま残る（同じ`--operation-id`で再実行すれば、同じ文書へ質問する）。
- 回答案は、管理UIの入力ごとに保存の操作になる（300msごとにまとめる）。
- 回答の内容は、stateに保存する。logには残さない。

# ADR-0010: 検索は節の単位で行い、語の一致と連続した文字列の一致を併用する

状態: 採用（P4）

## 背景

仕様9章は、Agentが開いている文書から必要な部分だけを取得できることを求める。日本語は空白で語が区切られないので、空白での分割だけでは取りこぼす。検索結果は、公開済みの版と対応していなければならない。

## 決定

- indexの単位は節（section）。Markdownはroot直下の見出しで区切り、最初の見出しより前は序文（`sec_0000`）にする。見出しも本文もない文書も、空の序文を1つ持つ（検索で返した節を、同じIDで取得できるようにする）。HTMLはparse5で静的に解析し、見出し要素で区切る。scriptは実行せず、script・style・template・入力欄の値は取り出さない。節の原文での位置は返さない（解析結果に位置がないため）。
- 検索用の文字列は、NFKCと小文字化をした派生の値。語への分割は`Intl.Segmenter`（日本語、語の単位）と、英数identifierの分割を使う。identifierは、分けた部分に加えて、分ける前の形も語にする。
- 語の一致はMiniSearchで調べる。fieldの重みは、文書のtitle 5、節の見出し 4、path 3、本文 1、上位の見出し 1。titleとpathは、文書の先頭の節にだけ入れる。すべての語が一致する節だけを返し、語を減らした検索へは切り替えない。
- 語への分割で取りこぼす連続した文字列は、正規化した本文への部分一致で拾い、候補へ加える。正規表現は受け付けない。`exact`と`path`は、空白を含めて指定どおりの文字列で照合する。`text`だけは、語の区切りの違いを問わないよう、連続した空白をそろえてから照合する。
- 一致の種類は、file名・pathの完全一致、連続した文字列の一致、語の一致、前方一致、綴りのゆらぎの順に強い。前方一致は2文字以上の語だけ、綴りのゆらぎは英数の4文字以上の語で、語の長さによらず1文字違いまで。英数だけのqueryが語の途中までしか一致しない場合は、前方一致として扱う（これも2文字以上のqueryだけ）。
- 順位は、一致の種類、score、一覧での順番、節の順で決める。1つの文書から返すのは2件まで。
- indexは別のthreadに置き、保存はしない。daemonの起動のたびに、保存済みの文書から作り直す。
- 文書の解析（節への分割）は、解析用のworkerで行う。indexのworkerは、解析済みの節を「始める→何回かに分けて入れる→確定する」の順で受け取り、確定するまで検索に出さない。長い本文と長い見出しは16Ki文字ずつ4Ki文字を重ねて分ける（分けた境目をまたぐ連続した文字列も、どれかの部分に含まれる）。見出しの全文は、workerが分けた部分から組み立てる。上位の見出しは、配下の節ごとに複製せず、親の節の番号でたどる。1回に送る量は、索引に入れるfield（見出しと本文）の長さで64Ki文字、部分の数で256件までに、上限を超える前に区切る（上限を超えるのは、1つの部分だけで超える回だけで、最大32Ki文字）。こうして、indexを作っている間も、検索はその1回分しか待たない。
- 語の一致は、語ごとにMiniSearchで引き、節の単位でまとめて、すべての語が同じ節に現れるかを判定する（分けた部分ごとに判定すると、離れた部分にある語の組み合わせを取りこぼす）。上位の見出しにある語は、配下の節の一致として、本文と同じ重み（見出しのfieldだけのscoreの1/4。上位の節のtitle・path・本文への一致は引き継がない）で数える。scoreは語ごとの最も高い部分のscoreの合計。結果も節の単位で返す。抜粋に使う部分は一致の種類とは別に選び、本文に一致した部分を優先する（見出しの連続した一致で種類が上がっても、本文の一致した部分を使う）。
- title・path・順番だけの変更は、本文を入れ直さずにindexへ反映する。反映するまでは、その文書は追い付いていないものとして扱う（待機の判定、`indexingDocuments`と`searchedDocuments`の集計、一覧の`searchState`で同じ判定を使う）。
- 登録の途中で文書が閉じられたり版が進んだりしたら、入れかけた内容を捨て、その登録の記録も消す。次の同期で改めて入れ直す。workerが内容を持ちうる文書は、登録の記録とは別に覚えておき、閉じた文書には、前に確定した内容も含めて必ず削除を送る。
- 検索は、始めた時点の一覧に対して行い、indexの反映を、検索を始めてから最大2秒待つ（やり直しの分も含める）。返す前に、開いていて、版・title・pathが一致するhitだけに絞る。検索の間に状態が変わったら1回だけやり直し、それでも合わなければ`incomplete`にする。検索できない文書（解析の失敗、登録中、読めなくなった文書）は、IDを示して返す。対象の文書が1件も検索できないときは、0件の結果と区別できないので、`E_INDEX_NOT_READY`にして、失敗と登録中の内訳を`details`に入れる。
- `catalogVersion`は、開いている文書・順序・公開している版・文書を読めるかどうかが変わったときに増える。indexへの反映の完了では増やさない（stateの保存を伴うため。仕様9.3との違い）。
- 検索と一覧のcursorは、署名付きで、操作・query・条件・一覧の版に固定する。5分で失効する。検索のcursorは、さらに、全hitの並び（文書・版・節）のdigestにも固定する。indexへの反映が進んで並びが変わったら（`catalogVersion`は同じでも）、続きを返さずに`E_CURSOR_STALE`（`reason: results`）にする。続きの検索では、検索の後にも一覧の版を確かめ、変わっていれば`E_CURSOR_STALE`（`reason: catalog`）にする。続きの検索はやり直さない。仕様9.3の「indexのgeneration」の代わりに、cursorが依存する並びそのものを固定する（関係のない文書の登録で、続きを失効させない）。

## 影響

- 意味の近さでの検索はしない。scoreは検索の中での相対的な値である。
- 大きい文書の登録に時間がかかると、その文書は一時的に検索できない。結果には、検索できなかった文書が示される。
- indexへの反映の途中でページを続けると、`E_CURSOR_STALE`になることがある。最初から検索し直す。
- 解析は、表示用の解析と同じworkerで順に行う。解析の時間の上限（2秒）を超える文書は、検索できない文書として示す。ほかの文書の時間切れの巻き添えで失敗した解析は、1回だけやり直す。
- 検索用の正規化した本文を、worker thread のmemoryに持つ。

# ADR-0007: file監視は通知と照合を併用し、監視ruleは再走査で登録する

状態: 採用（P2）

## 背景

仕様8.5は、fileの親directoryを監視してatomicな保存や作り直しを検知すること、無関係なdirectoryを丸ごと監視しないこと、通知の欠けから回復できることを求める。P0の契約テストで、Chokidarが監視開始の直後の変更を通知しない場合があることを確認している。

## 決定

- 監視するのは、開いている文書の親directory（直下だけ）と、`--watch`のruleの起点だけ。globのruleは、wildcardを含まない先頭部分までを起点にする。
- 通知を受けたら、対象ごとに200msまとめてから処理する。
- 文書の更新は、通知を契機にfileを読み直して判定する。内容が同じなら版を増やさない。一時的に消えているfileは最大1秒待ち、それでも無ければ`missing`にする。
- 通知だけに頼らない。監視の準備ができた時点と、5秒ごとに、開いている文書の`ino`・大きさ・更新時刻を照合し、違っていれば読み直す。
- ruleの対象は、matcherを別に持たず、通知を契機に登録時と同じ列挙（directoryの走査またはglobの展開）をやり直して差分を登録する。30秒ごとにも再走査する。
- 閉じた文書のpathは、範囲に入るruleの`suppressedPaths`へ入れ、再走査で復帰させない。明示的に開くと解除する。

## 影響

- 列挙の規則（対象の拡張子、隠しfile、除外directory、symlinkを辿らない）が、登録時と監視時で必ず一致する。
- 再走査はruleの範囲の大きさに比例して時間がかかる。開いている文書と閉じた文書は、本文を読まずに除く。
